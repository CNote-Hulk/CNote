LESSON: 6.1 – Secvența de pornire

---

CONCEPT: Power Sequence – secvența completă de pornire

VERIFIED INFORMATION:
Secvența de pornire: 1) Buton pornire → PS_ON activează sursa. 2) Sursa generează rail-uri (+3,3V, +5V, +12V), stabilizare 100–500 ms. 3) Power Good (PWR_OK) = +5V pe pin 8 (gri) — nu mai devreme de 100 ms după stabilizare, rămâne HIGH cel puțin 16 ms după pierderea AC, scade sub 0,4V cu cel puțin 1 ms înainte ca rail-urile să iasă din specificații. 4) Timer procesor eliberează linia de reset; CPU citește reset vector (x86 32/64-bit: FFFFFFF0h, 16-bit: FFFF0h); northbridge direcționează citirea către flash BIOS. 5) POST. 6) Scanare Option ROM. 7) Boot loader → OS.

---

CONCEPT: Inițializarea hardware (POST)

VERIFIED INFORMATION:
POST (Power-On Self-Test) = secvența de teste de diagnostic a firmware-ului la pornire. Verificări: registre CPU, checksum BIOS, controler DMA, timer sistem, controler de întreruperi. Inițializări (în ordine): CPU → chipset → RAM (prin SPD) → placa de bază → placă video → tastatură → mouse → HDD/SSD → unitate optică. Cold boot = POST complet; warm boot (Ctrl+Alt+Delete) poate ocoli unele teste prin flag CMOS. Scanare Option ROM: BIOS scanează 0x0C0000–0x0F0000 pe granițe de 2 KB, caută semnătura 0x55 0xAA, execută codul fiecărui ROM. Actualizări microcode: încărcate din BIOS flash în SRAM CPU la fiecare pornire (ne-persistente).

---

CONCEPT: Semnale de pornire

VERIFIED INFORMATION:
PS_ON: semnal de control care pornește sursa (buton → activare). Power Good (PWR_OK): +5V de la sursă, confirmă tensiuni stabile, recepționat de timer-ul care controlează reset CPU; sursele ieftine conectează Power Good direct la +5V (fără monitorizare separată — risc). Reset CPU: la eliberare, CPU citește prima instrucțiune de la reset vector. Beep codes: IBM (1 scurt = OK, continuu = PSU/placă/RAM, 1 lung + 2 scurte = video), AMI (1 = reîmprospătare memorie, 2 = paritate, 3 = read/write RAM, 4 = timer, 5 = procesor). POST card: dispozitiv diagnostic pe portul I/O 0x80. Boot sector signature: 0x55 0xAA verificată de BIOS înainte de transfer la boot loader.

---

CONCEPT: Procesul de boot (încărcarea OS)

VERIFIED INFORMATION:
BIOS legacy: interrupt 19h → parcurge lista de dispozitive de boot → încarcă primul sector (512 bytes) → verifică 0x55AA → încarcă la adresa 7C00h → CPU în real mode → MBR verifică tabela de partiții → găsește partiția activă → încarcă VBR → boot loader-ul OS (BOOTMGR, NTLDR, GRUB) → kernel OS. MBR: 446 bytes cod + 64 bytes tabelă partiții + 2 bytes semnătură. UEFI (modern): nu se bazează pe boot sectors, încarcă direct EFI application de pe EFI System Partition, suportă Secure Boot, Intel a eliminat suportul BIOS legacy din 2020, necesar pentru Windows 11.

---

CONCEPT: Aplicație în console de jocuri

VERIFIED INFORMATION:
Consolele urmează aceleași principii: alimentare → Power Good → inițializare firmware proprietar (echivalentul BIOS) → verificări hardware → încărcare OS. Sursa internă sau externă generează tensiuni, VRM-uri pe placa de bază convertesc pentru APU/GPU/RAM. Firmware-ul consolei verifică integritatea hardware-ului, inițializează componentele, apoi încarcă sistemul de operare de pe stocare internă.
